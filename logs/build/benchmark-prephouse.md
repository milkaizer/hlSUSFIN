# prep-house 벤치마킹 분석 (Step A-2)

조사일: 2026-10-26
대상: https://www.prep-house.co.kr
조사 폭: 데스크톱 1440x900, 모바일 390x844
조사 페이지: `/home`, `/Order_lectures`(주문·요금), `/info_VPT`(강의 상세)
도구: Cowork 내장 브라우저. 레이아웃은 스크린샷, 수치는 `getComputedStyle` 실측
최종 반영 대상: Vita Language 공개 페이지와 디자인 토큰

> 이 문서의 수치는 전부 실제 DOM 계측값이다. 눈대중이 아니다.
> prep-house는 GRE 전문 인강 사이트이고 우리는 어학 과목 4개 + 단계 3개다. 구조는 비슷하지만 상품 수가 다르다. 아래 "우리에게 옮길 때" 항목에서 그 차이를 반영했다.

## 0. 한눈에 보는 결론

prep-house의 핵심은 **"상품 카드 하나에 구성·기간·가격을 고정 라벨 격자로 박아 넣고, 모바일에서는 그 카드를 통째로 균일 축소한다"** 는 것이다. 라벨 폭을 58px로 고정하고(모바일 50px) 라벨을 값보다 작고 굵게 둬서, 390px에서도 가격 4요소가 한 줄에 들어간다.

중요한 기법 하나: **모바일에서 카드의 모든 값이 정확히 0.875배로 함께 줄어든다.** 폰트, 패딩, 모서리 반경, 라벨 폭, 카드 크기 전부 같은 계수다. 속성을 하나씩 반응형으로 조정하는 게 아니라 컴포넌트를 통째로 스케일한다. 그래서 내부 비율이 깨지지 않는다.

두 번째 핵심은 **역할 분리**다. 강의 상세 페이지에는 가격이 아예 없다(실측 확인). 설득은 상세 페이지, 거래는 주문 페이지로 완전히 갈라놨다.

세 번째는 **신뢰 자산의 배치**다. 평균 점수 → 후기 → 합격자 순으로 세 섹션을 연달아 놓고, 그다음에야 상품을 보여준다.

## 3. 히어로 (`.head-s`)

- 섹션 패딩 `96px 0`, 전체 중앙 정렬
- 윗줄(작은 글씨): 도발형 한 문장
- 메인 제목 `p.h2`: **56px / weight 800 / `rgb(57,69,95)` / center**
  - 문장 일부만 강조색 + 밑줄로 처리
- 본문 6줄, 각 줄이 독립된 주장 (문단이 아니라 불릿 없는 목록처럼 읽힌다)
- CTA 버튼 1개, 알약형

**관찰**: 히어로에 이미지가 없다. 56px 타이포 하나로 화면을 장악한다. 본문 6줄은 숫자를 계속 던진다(누적 문제 수, 업데이트 문제 수 등). 추상적 형용사가 아니라 수치로 밀어붙이는 방식이다.

**우리에게 옮길 때**: 56px는 그대로 쓰기엔 크다. 우리 히어로는 40~48px 선이 적당하다. 문장 일부만 강조색 처리하는 기법, 본문을 문단이 아니라 짧은 주장 줄로 쪼개는 기법은 그대로 가져갈 만하다. 숫자를 못 쓰면(아직 실적이 없으면) 이 패턴은 약해지니 주장 줄 수를 3~4줄로 줄이는 게 낫다.

## 4. 강의 카드 (가장 중요)

### 4-1. 홈의 강의 카드 (`.p-lecture` 캐러셀)

Swiper, `slidesPerView: "auto"`, `spaceBetween: 30`, 슬라이드 9장(강의 9개), 루프 없음.

| 항목 | 데스크톱 1440 | 모바일 390 |
|---|---|---|
| 카드 폭 | 400px | 360px |
| 카드 높이 | 481px | 421px |
| 모서리 | `border-radius: 40px` | `35px` |
| 배경 | `#FFFFFF` | 동일 |
| 그림자 | **none** | 동일 |
| 한 화면 노출 | 약 2.6장 | 1장 |

카드 내부 (`.lecture`, 데스크톱 패딩 `280px 32px 36px`):

```
+------------------------------+
|                              |
|      [제품 3D 이미지]         |  <- .l-cube, 352x386, 상단 패딩 280px로 자리 확보
|                              |
+------------------------------+
| Word PRO(TM) Basic           |  <- p.h3  28px / 800 / #3F3F3F
|                              |     "(TM)"는 sup 21px, 뒷단어는 weight 400
| 강의 구성  20 Videos + Extra  |  <- 라벨 12.8px/700 #666F84, 폭 고정 58px
| 수강 기간  60일  기본 30일+..  |     값 16px/600 #636C81, 보조 14px
| 수강료   [취소선 250,000] [Event Price] 150,000 won |
+------------------------------+
```

**라벨·값 격자가 이 사이트의 핵심 장치다.**

- 라벨 3개 고정: `강의 구성` / `수강 기간` / `수강료`
- 라벨 폭을 **58px로 고정**(모바일 50px)해서 값 시작점이 세로로 정렬된다
- 라벨은 12.8px/700, 값은 16px/600. 크기 차이로 위계를 만들고 색은 거의 같게 둔다
- 390px에서는 격자가 사라지지 않고 **통째로 0.875배 축소**된다. 라벨 11.2px / 폭 50px, 값 14px. 비율이 같으므로 줄바꿈이나 스택 전환이 일어나지 않는다

가격 행 구성 (한 줄에 4요소). 아래는 데스크톱 기준, 모바일은 전부 0.875배:

| 요소 | 스타일 |
|---|---|
| 원가 | `<del>` 16px/600, 취소선 |
| Event Price 배지 | 10px/700, 글자·테두리 `rgb(0,191,220)`, 테두리 약 0.76px, radius 5px, padding 약 1.75/3 |
| 할인가 | `<strong>` 16px/700 |
| 단위 | "won" 소문자, 가격보다 작게 |

**관찰**: 할인가가 원가보다 눈에 띄게 크지 않다. 16px/700 대 16px/600, 차이는 굵기뿐이다. 대신 그 사이에 끼워 넣은 **작은 형광 배지**가 시선을 잡는다. 가격을 키우는 대신 배지로 처리하는 절제된 방식이다.

> **계측 주의.** 이 사이트는 **페이지 로드 시점의 뷰포트 폭**에 따라 카드 컴포넌트 스케일을 결정한다. 좁은 폭에서 로드한 뒤 창을 넓히면 축소된 스타일이 그대로 남는다. 계측할 때는 원하는 폭으로 맞춘 뒤 **반드시 새로 로드**해야 한다. 이 문서의 수치는 각 폭에서 재로드 후 측정한 값이다.

### 4-2. 주문 페이지의 강의 카드 (`/Order_lectures`)

Bootstrap 그리드 `col-lg-4` → 데스크톱 3열(카드 폭 390px, 높이 526px), 390px에서 1열(폭 390px, 높이 489px).

```
+--------------------------------+
|  [표지 이미지 밴드]              |  <- 파랑 그라디언트, 제품명 큰 글씨 중앙
|  (기기 아이콘)      한국어 (국기) |     좌하단 지원기기, 우하단 언어
+--------------------------------+
| Word PRO(TM) Basic             |  <- 제목
| 강의 개수 : 20 Videos + 10 Extras|  <- 라벨에 콜론, 인라인
| 수강 기간 : 60일 기본 30일+..    |     "60일" 굵게, 뒤 보조문구 작게·회색
|               [취소선 250,000 won] |  <- 우측 정렬
|           [EVENT] 150,000 won  |     EVENT는 청록 채움 배지
+----------------+---------------+
|   강의정보      |    주문하기    |  <- 2분할 텍스트 버튼, 가운데 세로 구분선
+----------------+---------------+
```

**관찰 3가지**

1. 홈 카드와 주문 카드의 라벨이 다르다. 홈은 `강의 구성`, 주문은 `강의 개수`. 같은 상품인데 용어가 흔들린다. **이건 따라 하면 안 되는 부분이다.**
2. 카드 하단을 두 버튼으로 정확히 반 나눈다. 정보와 구매를 같은 무게로 둔다.
3. **단독 구매가 불가능한 상품**(IDIOM PRO, Verbal 600, Quant PRO Basic)은 가격 블록 자리에 안내 문구를 넣고, 버튼은 `강의정보` 하나만 전체 폭으로 둔다. 카드 틀은 똑같이 유지한다.

**우리에게 옮길 때**: 3번이 우리 결제 비활성 요건과 정확히 맞는다. **결제 버튼을 disabled로 두는 대신, 같은 자리에 "준비 중" 안내를 넣고 버튼을 하나로 줄이는 방식**을 쓰면 비어 보이지 않으면서 결제 비활성 요건도 지킨다. 다만 HANDOFF가 disabled 버튼을 명시했다면 disabled를 유지하고 안내 문구만 추가하는 선에서 절충해야 한다. 용어는 `구성 / 기간 / 수강료`로 홈과 과목 페이지에서 **한 벌로 통일**할 것.

## 5. 패키지 상품 제시 방식

주문 페이지는 **3단 깔때기**로 짜여 있다.

### 1단: ALL PACK (플래그십)

화면 폭 전체를 쓰는 어두운 네이비 패널. 우측에 3D 큐브 제품 이미지.

| 라벨 | 값 |
|---|---|
| 강의구성 | 개별 강의 8개를 **전부 나열** |
| 수강기간 | **총 6개월** (기본 2개월 + 무료 연장 4개월) |
| 수강가격 | Original Price 930,000 won → Package Price 620,000 won |

CTA: `ALL PACK 주문하기` + `내용 더보기`. 상단에 알약형 태그 `Shorter GRE 무료업데이트 포함`.

### 2단: ALL PACK OPTIONS

해외결제, 차액 업그레이드. 본 상품 바로 아래 **같은 줄에 2칸**으로 붙인다.

### 3단: VERBAL PACK (중간 묶음) + 업그레이드 2종

좌측에 포함 강의 표지들을 **비스듬히 겹쳐 쌓은 이미지**, 우측에 같은 라벨 격자(강의구성/수강기간/수강가격 450,000won)와 전체 폭 `주문하기`.

그 아래 Upgrade 1 / Upgrade 2를 2칸으로 배치. 각 칸에 **자격 조건을 한 줄로 먼저 쓰고** 가격을 쓴다.

- Upgrade 1: "Word Pro Basic 또는 Essentials 구입 회원" → 300,000won
- Upgrade 2: "Word Pro Basic, Essentials을 모두 구입한 회원" → 150,000won

### 4단: 개별 강의 9개 3열 그리드 → 구매 회원 전용 콘텐츠

**관찰**: 묶음이 개별보다 **위에** 있다. 비싼 것부터 보여주고 내려온다. 묶음 가격은 항상 `원가 → 패키지가` 2단 표기이고, 할인율(%)은 어디에도 쓰지 않는다. 숫자 두 개를 나란히 놓고 독자가 계산하게 둔다.

또 하나: **"총 6개월 (기본 2개월 + 무료 연장 4개월)"** 처럼 기간을 합계와 내역으로 쪼개 쓴다. 개별 강의도 "60일 (기본 30일 + 무료서비스 추가 30일)" 동일 패턴. 혜택을 기간 표기 안에 녹였다.

**우리에게 옮길 때**: 우리 단계 3개(`content/tiers.ts`)에 이 구조가 그대로 들어맞는다.
- 상위 단계를 **맨 위에 가장 크게**, 하위 단계로 내려가며 카드를 작게
- 각 단계 카드에 `구성 / 기간 / 수강료` 동일 라벨 격자
- 가격은 `정가 → 제공가` 2단, 할인율 표기 없음
- 기간은 "총 N개월 (기본 X + 추가 Y)" 형태로 혜택 내장
- 업그레이드·조건부 상품은 **조건 문장을 가격보다 먼저** 쓴다

## 6. 후기·합격자 영역

### 6-1. 평균 점수 + 후기 (`.s-review`, 720px)

좌: 큰 네이비 라운드 패널.
- 제목 18px/700 흰색
- 점수 3개 가로 배열, 세로 구분선. 라벨(Verbal/Quantitative/Writing)은 **이탤릭 소문자**, 값은 아주 큰 흰색 숫자
- 그 아래 실제 성적표 이미지 3장을 **비스듬히 기울여** 겹쳐 배치

우: 흰 패널
- 후기를 인용하지 않고 **카테고리 목록**만 불릿으로 제시 (만점 후기 / 입학후기 / 기간별 후기 / 타 학원출신 후기 / 직장인·예체능 후기)
- CTA (청록 채움, 19.2px/700, radius 9.6px, 높이 51px)
- 하단에 작은 보조문구

**관찰**: 후기 본문을 홈에 전혀 싣지 않는다. 대신 **후기의 종류**를 나열해서 "내 상황에 맞는 후기가 있다"를 전달하고 클릭을 유도한다. 후기 콘텐츠가 적을 때도 성립하는 구조다.

### 6-2. 합격자 (`.acceptance`, 429px)

- 제목 20px/700 `rgb(19,29,44)` 중앙
- 가로 무한 티커. 카드 한 장 = 흰 배경 + 라운드 + **대학 엠블럼** + 대학명 + `석사`/`박사` + 마스킹 이름
- 데스크톱 약 7장, 모바일 약 2.5장 노출. 동일 목록을 3회 반복해 끊김 없이 흐른다
- 하단 작은 회색 고지: 개인정보보호법 근거와 블라인드 처리 안내

**관찰**: 정보량이 카드당 4조각뿐이다(로고·학교·학위·이름). 적은 정보를 많은 장수로 밀어서 물량감을 만든다. 개인정보 고지를 바로 아래 붙인 것도 그대로 참고할 만하다.

**우리에게 옮길 때**: 우리는 합격자·후기 둘 다 스페이서 플래그 상태다. **티커 구조는 데이터 0건일 때 가장 어색해진다**(빈 띠가 흐른다). 플래그가 꺼져 있으면 티커 대신 고정 높이 스페이서를 두고, 플래그가 켜지면 티커로 전환하는 분기를 권한다. 6-1의 "카테고리 목록 + CTA" 패턴은 후기 0건일 때도 자연스러우니 이쪽을 먼저 쓰는 게 낫다.

## 7. 공지

두 군데에 있다.

**최상단 띠 (`.small-pop.s2`, 46px)**: 검정 배경, `공지` 라벨(청록) + 제목 + 알약형 테두리 버튼. 페이지 맨 위, 네비게이션 바로 아래. 모바일에서는 버튼이 앰버색으로 바뀐다.

**우리에게 옮길 때**: 상단 띠 + 하단 카드 2단 구성은 우리 공지 요건에 그대로 맞는다. 띠는 공지가 있을 때만 렌더하고 섹션 순서에서 빠지게 해야 `data-section` 기대값이 흔들리지 않는다.

| 측정 | 데스크톱 1440 | 모바일 390 |
|---|---|---|
| 홈 전체 높이 | 7093px | 8440px |
| 주문 페이지 | 5261px | 9631px |
| 강의 상세(`/info_VPT`) | 12225px | 미측정 |
| 홈 섹션 수 | 12 + 푸터 | 동일 |

섹션 세로 패딩이 크다: `.about`과 `.news` `192px 0`, `.cafe`와 `.s-review` `160px`, `.head-s` `96px`, `.acceptance` `70px`.

**이 사이트의 밀도 전략은 이중적이다.**

- **섹션 사이**는 아주 넓게 띄운다 (160~192px)
- **카드 안**은 아주 빽빽하다 (행 높이 약 26~27px, 라벨 12.8px)

즉 "멀리서 보면 여유롭고, 가까이 보면 정보가 꽉 찬" 구성이다. 카드 하나를 읽기 시작하면 구성·기간·원가·할인가·혜택기간을 3행 안에서 전부 얻는다.

강의 상세 12225px는 극단적이다. 좌측 앵커 네비(`ABOUT / FEATURE / HOW TO STUDY / FAQ`, `.local-scroll`, 폭 390px)로 길이를 감당한다. 섹션 제목은 24px/700로 일정하고, 흰 배경 구간과 어두운 이미지 구간을 번갈아 배치해 리듬을 준다.

**우리에게 옮길 때**: 192px는 콘텐츠가 많을 때 성립한다. 우리 섹션 수가 적으면 과도하게 비어 보인다. **섹션 패딩 96~120px, 카드 내부는 prep-house만큼 빽빽하게**가 우리 규모에 맞는 절충이다.

## 10. 타이포 위계

`html { font-size: 10px }`. 모든 값이 rem 기반이라 계측값이 10 단위로 떨어진다.
본문 폰트: `"Noto Sans KR", "Open Sans", -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`
영문 제목에는 별도 `f-mont` 클래스(Montserrat 계열)를 쓴다.

| 역할 | 데스크톱 1440 | 모바일 390 | 배율 | weight | 색 |

**핵심 규칙 2개**

1. **반응형 축소가 두 갈래다.**
   - **컴포넌트 균일 스케일 0.875**: 카드와 일반 섹션 제목이 여기 속한다. 폰트뿐 아니라 패딩, 모서리, 라벨 폭, 카드 크기까지 같은 계수로 줄어든다. 속성을 하나씩 조정하지 않고 컴포넌트를 통째로 스케일하기 때문에 **내부 비율이 완전히 보존된다.** 라벨 대 값의 비(12.8:16 = 11.2:14)가 양쪽에서 동일하다.
   - **히어로만 별도의 강한 축소 0.46**: 56 → 25.9. 균일 스케일을 따르지 않는 유일한 요소다. 큰 디스플레이 타이포는 모바일에서 따로 다뤄야 한다는 판단이다.

   정리하면, **카드는 "줄이되 비율을 지키는" 대상이고 히어로는 "따로 다시 정하는" 대상이다.**
2. **위계를 색이 아니라 크기와 굵기로 만든다.** 라벨과 값의 색 차이는 `#666F84` 대 `#636C81`로 거의 없다. 12.8px/700 대 16px/600, 즉 작고 굵은 라벨 vs 크고 덜 굵은 값이다.

**우리에게 옮길 때**:
- 2번이 디자인 토큰에 바로 들어간다. 라벨 토큰(`text-[12.8px] font-bold`)과 값 토큰(`text-base font-semibold`)을 만들고 색은 거의 같게 둘 것.
- 1번은 그대로 베끼지 말 것. prep-house는 로드 시점 폭으로 스케일을 고정하는 구식 방식이라 **창 크기를 바꿔도 반영되지 않는다.** 우리는 Tailwind 브레이크포인트로 같은 결과를 내되, 카드 내부 값들을 **한 배율로 묶어서** 바꿀 것. 예: 카드 루트에 `text-sm md:text-base` 를 걸고 내부를 `em` 단위로 짜면 한 번에 비례 축소된다.
- `.btn-*`, `.panel`, `.field` 공용 클래스에는 이 스케일을 걸지 말 것. 관리자 화면과 My Class가 그 클래스를 쓰므로 축소가 전파되면 표가 깨진다.

## 11. 색 쓰는 방식

실측 색 빈도 상위 기준으로 정리했다. (브랜드 색 자체는 가져오지 않는다. 쓰는 **방식**만 본다.)

**중성 네이비 계열 (주력)**

| 색 | 용도 |
|---|---|
| `#131D2C` | 섹션 제목 |
| `#272F43` | 소개 제목 |
| `#39455F` | 히어로 제목 |
| `#2B4B6F`, `#333F5C`, `#233951` | 어두운 패널 배경 |

**회색 계열 (본문·라벨)**

`#707070` 본문 기준색, `#636C81` 카드 값, `#666F84` 카드 라벨, `#838DA5`, `#7E8796`, `#BFBFBF` 보조, `#3F3F3F` 카드 제목.

**강조색 (아주 좁게)**

| 색 | 쓰이는 곳 |
|---|---|
| `#00BFDC` | Event Price 배지 테두리·글자 |
| `#17E0FF` | 주 CTA 버튼 채움 |
| `#77FFFA` | 보조 CTA 버튼 채움 |
| `#50B7C7` | 외곽선 버튼 |
| `#2088DF`, `#095EC6` | 본문 링크 |

**배경**

페이지 `#F7F8FA` (순백 아님), 카드 `#FFFFFF`, 푸터 `#252525`.

**관찰 3가지**

1. **강조색은 전부 청록 한 계열이다.** 빨강은 주문 페이지 `EVENT` 배지 하나에만 등장한다. 색 종류를 늘려 위계를 만들지 않는다.
2. **카드에 그림자가 없다.** `box-shadow: none`. 대신 페이지 배경을 `#F7F8FA`로 살짝 깔고 카드를 순백으로 띄운다. 그림자 대신 **배경 명도 차**로 입체를 만든다.
3. **CTA 버튼은 어두운 글자 + 밝은 형광 배경**이다. `#17E0FF` 바탕에 `#0A2243` 글자. 흰 글자 + 진한 배경의 반대다. 대비가 높고 밝은 면에서 눈에 띈다.

**우리에게 옮길 때**: 2번과 3번이 토큰에 바로 들어간다.
- `--surface-page: #F7F8FA` 같은 오프화이트 배경 + 순백 카드 + 그림자 없음 조합으로 `.panel` 토큰을 재정의
- 강조색은 **한 계열만** 정하고 변주(진함/연함/외곽선)로 역할을 나눌 것. 색을 늘리지 말 것
- 단, 푸터 대비(8장)는 따라가지 말 것

## 12. 버튼과 카드 모양

### 버튼 (실측)

| 유형 | 배경 | 글자 | 크기 | radius | 패딩 | 높이 |
|---|---|---|---|---|---|---|
| 주 CTA | `#17E0FF` | `#0A2243` | 19.2px/700 | 9.6px | 9.6 / 19.2 | 51px |
| 주 CTA (변형) | `#77FFFA` | `#146877` | 19.2px/700 | 9.6px | 9.6 / 19.2 | 51px |
| 외곽선 알약 | 투명 | `#50B7C7` | 16px/700 | **24px** | 8 / 12.8 | 36px |
| 고스트(어두운 배경) | 투명 | `rgba(255,255,255,.65)` | 14px/700 | **0** | 10 / 15 | 35px |
| 카드 하단 분할 | 투명 | 회색 | 소형 | 0 | - | - |

**패턴**: radius가 역할마다 다르다. 주 CTA는 **9.6px(완만)**, 보조 외곽선은 **24px(완전 알약)**, 푸터 고스트는 **0px(각짐)**. 모양으로 위계를 구분한다.

### 카드

| 유형 | radius | 그림자 | 테두리 |
|---|---|---|---|
| 홈 강의 카드 | 40px (모바일 35px) | 없음 | 없음 |
| 주문 페이지 카드 | 약 16px | 아주 옅음 | 1px 연회색 |
| 합격자 카드 | 중간 | 아주 옅음 | 없음 |
| 다크 패널 | 큼 | 없음 | 없음 |

**관찰**: 홈의 상품 카드는 radius 40px로 과감하게 둥글다. 반면 주문 페이지 실무 카드는 16px로 차분하다. **"보여주는 카드"는 둥글고, "일하는 카드"는 덜 둥글다.**

**우리에게 옮길 때**: radius 역할 분리(주 CTA 완만 / 보조 알약 / 유틸리티 각짐)는 토큰화하기 좋다. 다만 홈 40px는 우리 카드 폭이 더 좁으면 과하다. 홈 24~28px, 실무 카드 12~16px 정도가 안전하다. `.btn-*` 토큰을 바꾸면 관리자 화면에 전파되니 **유틸리티 버튼 radius는 건드리지 말 것**.

**가장 중요한 3가지**

1. **섹션 순서가 바뀌지 않는다.** 숨기는 섹션도, 순서 바꾸는 섹션도 없다. 전부 세로로 늘어날 뿐이다.
2. **카드가 통째로 0.875배 축소되고 내부 비율은 그대로다.** 라벨 폭 58 → 50, 라벨 12.8 → 11.2, 값 16 → 14, 패딩 280/32/36 → 245/28/31.5, 모서리 40 → 35. 전부 같은 계수다. 비율이 유지되므로 `수강료 | 250,000 | [Event Price] | 150,000 won` 네 요소가 390px에서도 한 줄에 들어간다. 요소를 빼거나 접지 않는다.
3. **점수 3개는 가로를 유지한다.** 세로 구분선까지 그대로다. 비교 대상은 세로로 쌓으면 비교가 안 된다는 판단이다.

추가: 모바일 푸터 우하단에 **맨 위로 가기** 떠 있는 버튼이 생긴다. 8440px 페이지라 필요하다.

**우리에게 옮길 때**: 1번이 우리 `data-section` 테스트와 직결된다. prep-house처럼 **순서를 반응형으로 바꾸지 않으면** `p1-public.spec.ts`, `p1-flags.spec.ts`의 기대값을 폭별로 분기할 필요가 없다. 순서 변경은 섹션을 추가·삭제할 때만 발생하도록 설계할 것. 2번은 390px 가로 스크롤 0 요건을 만족시키는 실전 기법이다.

## 15. Step A-3 반영 시 주의할 것

1. **공용 클래스 전파.** `.btn-*`, `.panel`, `.field`는 관리자 화면과 My Class가 쓴다. 토큰 변경 후 두 화면을 반드시 확인할 것. 특히 10장 1번의 **카드 균일 축소 스케일을 공용 클래스에 걸면 관리자 표가 함께 줄어들어 깨진다.** 스케일은 공개 페이지 카드 컴포넌트에만 한정할 것.
2. **섹션 순서 변경 시.** HANDOFF 6.1과 달라지면 `tests/e2e/p1-public.spec.ts`, `p1-flags.spec.ts`의 `data-section` 기대값을 같이 고치고 `logs/build/decisions.md`에 이유를 남길 것. 위 1장 표의 순서를 그대로 쓰면 프로모션 캐러셀과 강사진이 빠지므로 **순서 변경이 발생한다.**
3. **플래그 off 상태 설계.** 합격자 티커는 데이터 0건일 때 가장 어색하다. 플래그 off면 스페이서, on이면 티커로 분기할 것.
4. **결제 비활성.** 4-2장 3번 패턴(가격 자리에 안내 + 버튼 축소)을 쓰되 HANDOFF가 disabled 버튼을 명시했다면 disabled를 유지하고 안내 문구만 더할 것.
5. **390px 검증.** `document.documentElement.scrollWidth === window.innerWidth` 로 확인. prep-house는 홈·주문 양쪽 모두 통과한다.

### 검증 과정에서 바로잡은 것

작성 후 실측 재검증을 돌렸고 오류 하나를 찾아 고쳤다. 기록으로 남긴다.

- **증상**: 1차 조사에서 카드 내부 수치가 전부 정확히 0.875배로 나왔다(제목 24.5, 라벨 11.2, 값 14, 패딩 245/28/31.5). 1440px에서 측정했는데도 그랬다.
- **원인**: 이 사이트는 **페이지 로드 시점의 뷰포트 폭**으로 카드 컴포넌트 스케일을 고정한다. 1차 조사 때 브라우저 패널의 기본(좁은) 폭으로 먼저 로드한 뒤 1440px로 리사이즈했기 때문에, 좁은 폭용 스케일이 그대로 남아 있었다. 반면 섹션 패딩과 히어로 폰트는 순수 미디어 쿼리라 리사이즈에 즉시 반응해서 데스크톱 값을 보였다. 그래서 한 화면 안에서 두 체계가 섞여 보였다.
- **확인**: 1440px로 맞춘 뒤 **재로드**하니 제목 28px, 라벨 12.8px/58px, 값 16px, 패딩 280/32/36, 카드 400x481 r40. 전부 10px 루트 기준의 깔끔한 rem 값이다. 390px로 맞추고 재로드하면 다시 0.875배 값이 나온다.
- **문서 수정**: 0장, 4-1장, 10장, 13장, 14장의 카드 수치와 반응형 서술을 전부 교체했다. 1장 섹션 표의 `.p-lecture` 높이도 631 → 691, 문서 전체 높이 7035 → 7093으로 정정했다.
- **결론이 바뀐 지점**: 처음에는 "카드 타이포는 모바일에서도 안 줄어든다"로 썼는데, 사실은 **"카드가 통째로 0.875배 줄어들되 내부 비율이 보존된다"** 가 맞다. 우리가 가져갈 교훈은 후자다.
- **계측하는 사람에게**: prep-house를 다시 잴 일이 있으면 원하는 폭으로 맞춘 뒤 반드시 재로드할 것. 리사이즈만으로는 카드 수치가 갱신되지 않는다.
